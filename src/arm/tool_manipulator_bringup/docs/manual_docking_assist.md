# manual.launch.py의 버튼식 각도 정렬

수동으로 도킹 근처까지 접근한 뒤 L2+△(툴0) 또는 L2+○(툴1)를 누르고 놓는다.
한 번의 요청으로 DXL 기준 자세 준비와 RMD 각도 정렬을 실행한다.
완료 후에는 수동 조작만 수행하며, AprilTag로 위치를 계속 보정하지 않는다.

## 관절과 목표

1. DXL ID 1(base)은 현재 관절각에서 가까운 -180° 또는 +180°로 이동한다.
   ID 2(roll)는 0°로 이동한다. ID 3(yaw)는 툴0에서 0°, 툴1에서는 **L2+○를 누른 시점의
   실제 관절각을 유지**한다. 태그 획득·계획 시점의 값으로 다시 잡지 않는다.
   이 준비 단계에서 RMD 목표는 고정한다.
   **DXL 준비 단계는 TCP 위치를 변경할 수 있다.** 전체 경로를 실행 전에 검사한다.
   준비 구간의 예정 시간이 끝나도 바로 RMD 정렬을 시작하지 않는다. 준비 목표의 실제 관절 오차가
   0.005 rad 이내이고 TCP 위치 오차가 설정 허용치 이내일 때까지 검사된 준비 목표를 유지한다.
   대기 중에도 실행 timeout·추종 오차·EE 변화·취소 검사는 유지한다.
2. 준비가 끝나면 DXL 3축을 고정하고 RMD shoulder/elbow/wrist pitch만 움직인다.
   이 단계의 TCP 위치 기준은 DXL 준비 완료 자세이며, 위치를 유지하면서 기울기를 맞춘다.
3. 실제 `/joint_states`와 FK로 계산한 목표 자세 오차가 **±1° 이내**이고
   마지막 관절 목표에 도달해야 완료로 인정한다. ±1°는 사용자 지정값이다.

툴0은 태그 면의 수직 방향을 삽입축으로 사용한다. `Drawing1.stl`의 지정 원형 결합면과
태그 위치로 지정된 정사각형 음각 바닥은 평행하다. 원기둥 축과 회로박스 수평 상면의
예각은 모델상 약 **35°**다. 안쪽 방향은 아래쪽 35°다. 실제 태그가 음각 바닥에
밀착·평행하게 붙어 있어야 한다. 목표는 매 요청의 태그 관측에서 얻고 35°로 강제 덮어쓰지 않는다.

툴1은 사용자의 요청에 따라 **카메라 영상면을 태그 면과 평행하게 맞춘다.**
카메라 Optical +Z와 태그 법선 방향을 맞추고, 실제 TCP↔Optical TF를 적용한다.
**툴1의 카메라 정렬 완료는 홀 삽입축 정렬 완료를 뜻하지 않는다.** 홀의 정확한 각도는
미확인 상태이므로 최종 삽입 각도는 수동 조정한다. 진단의 `alignment_reference`는
툴0 `insertion_axis`, 툴1 `camera_plane`으로 구분된다.

DXL 고정 조건에서 RMD 3축으로 맞출 수 없는 좌우 방향 오차, IK 불가, 관절 제한,
TCP 위치 이탈 또는 충돌이 있으면 전체 요청을 거부한다. DXL을 몰래 풀거나
다른 축으로 우회하지 않는다. EE 체결 동작은 자동 실행하지 않는다.

## 조작과 중단

| 입력 | 동작 |
| --- | --- |
| L2+△ | 툴0 각도 정렬 1회 요청 |
| L2+○ | 툴1 카메라 정렬 1회 요청 |
| 정렬 중 같은 조합 | 취소; 중립 후 다시 요청 |
| 완료 후 같은 조합 | 새 태그 관측으로 새로운 정렬 요청 |
| × 단독 / △ 단독 | 도킹 잠금 true / 해제 false 1회 발행 |
| □ | 정렬 취소 후 기존 HOME |
| L2+× | 정렬 취소 후 기존 툴2 경로 요청 |
| R2+스틱 | 완료 후 기존 자세 유지 수동 이동 |

L2와 선택 버튼을 놓고 중립을 확인해야 정렬이 시작된다. 정렬 실행 중 수동 이동 입력은
정렬을 취소한다. 조이스틱·관절 피드백 유실, focus 변경, fault도 정지시킨다.
취소·실패 후 태그 재등장만으로 다시 움직이지 않는다.

정렬은 요청 이후의 유효한 태그 관측 3개를 확인한 뒤 목표를 한 번 고정한다.
후속 태그 관측으로 실행 경로를 다시 계산하지 않는다. 정렬 실행 중에는 태그 최신성을
확인하지만, 완료 후 태그가 안 보여도 저장된 목표와 실제 자세의 오차 판별 및 수동 이동은 가능하다.
일반 조이스틱 입력으로 자세를 바꾸어 ±1°를 벗어나면 완료 상태가 해제되며,
자동으로 다시 정렬하지 않는다. R2 이동은 기존과 동일하게 베이스 방향 수평/수직 이동이며
TCP 삽입축을 자동 추종하는 기능이 아니다.

## 실행과 진단

`manual.py`가 기존 position controller의 유일한 명령 주체다. 공유 `ArmKinematics.solve`를
RMD 3축으로 제한해 사용하며, 전체 경로를 별도 계산 작업에서 완성한 뒤 실행한다.
DXL 준비와 RMD 경로를 모두 `GetStateValidity`로 검사한다. 런치에서 기존 MoveIt
`move_group`의 계획 장면 서비스만 시작하며 `allow_trajectory_execution=false`다.
MoveIt Servo나 별도의 모터 명령 노드는 사용하지 않는다.
사용자 요청으로 그리퍼 핑거 `rack_left`, `rack_right`의 collision 형상만 정렬용 계획 장면에서 제외한다.
실제 구동 URDF, 시각화와 핑거 구동은 유지하며 다른 링크의 충돌은 계속 검사한다.
일반 수동 조작에는 기존 충돌 검사 비활성 동작이 유지된다. 정렬 경로 검사는 모델에
포함된 형상에 대한 검사이며, 모델에 없는 장애물·접촉력·기구 공차를 판별하지 않는다.

기존 CameraInfo, 태그 코너 입력 `/arm/apriltag/centers`, 이미지 시각의
`base_actuator <- arm_camera_color_optical_frame` TF와 PnP를 재사용한다.
툴1에는 추가로 같은 시각의 `tcp_link <- optical_frame` TF가 필요하다.
태그 법선 부호는 관측 카메라에서 태그 쪽으로 향하도록 결정한다.
카메라/태그 인식 노드는 별도로 실행해야 한다.

`/manual/diagnostics.docking_assist`와 실행 터미널에서 다음을 확인한다.

- `TAG_NOT_DETECTED`: 새 요청에 유효한 태그 입력을 기다리는 상태.
- `ALIGNMENT_READY`: 실행 전 경로 검사 중, 또는 수동 자세 변경으로 재정렬이 필요한 상태.
- `ALIGNING`: DXL 준비 또는 RMD 정렬 중. `status`로 두 단계를 구분한다.
- `ALIGNMENT_OK`: 실제 각도 오차가 허용 범위 안. 툴1은 로그에 `CAMERA_ALIGNMENT_OK`로도 표시한다.
- `ALIGNMENT_FAILED`: 실패 원인을 기록하고 수동 복귀 전에 중립을 요구한다.
- `monitoring_only=true`: 자동 이동이 끝났으며 현재 자세만 판별한다.
- `angle_error_deg`: 실제 피드백과 고정 목표 사이의 각도 오차.

서비스 `/manual/docking/cancel` (`std_srvs/Trigger`)로 취소할 수도 있다.

## 미검증 값

관절 제한·모터 zero·URDF 기구 길이는 변경하지 않았다. 35°는 모델 측정값이고
±1°와 DXL 기준 자세는 사용자 지정값이다. 다음 값은 실기 정확도 보장이 아닌
초기 제어 설정이며 코드/YAML에 표시했다.

- RMD 정렬 중 TCP 위치 오차 제한 1 mm, IK 자세 간격 0.02 rad.
- 충돌 검사 관절 샘플 간격 0.005 rad(기존 manual collision 값).
- 관절 속도 최대 0.06 rad/s, 가속도 최대 0.25 rad/s²(기존 제어 값 재사용).
- 계획/충돌 검사 제한 30초, 실행 예상 시간에 피드백 여유 30초.
- 관절 목표 도달 판정 0.005 rad, EE 변화 감시 0.01 rad(기존 경로·충돌 허용값 재사용).
- 태그 최대 나이 0.25초, 획득 제한 5초, 안정 관측 3개 및 기존 영상 품질 기준.

태그→TCP 위치 오프셋은 참고값으로 남아 있으나 이번 각도 정렬의 TCP 위치 목표에는
사용하지 않는다. 가상 검증 코드·가상 태그·시험 결과는 Git에서 제외한 로컬 파일에만 보관한다.
